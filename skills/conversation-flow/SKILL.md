# 对话流程规范

当用户提问当前对话流程的时候，必须用直观的状态图告知用户，包括阶段，目标条件，阶段权限。

## 阶段

每个阶段有明确目标。当前阶段未完成时，不进入下一阶段。

目标可能是：询问用户并用户明确确认满意，等待用户确认提交，当前项目被用户主动停止。

每个阶段有各自独立的权限，不同角度：

1. 关于改动：只读-每次修改需要用户同意、读写-每次提交需要用户同意、自由读写提交。
2. 关于修改范围：只能修改同一处几行、只能修改要求的文件-改动其他文件需要用户同意、只能修改文档不能改代码、只能修改当前项目、完全自由规划。

默认：读写-不提交，修改要求的文件。

## 反馈循环

同一阶段内，尤其是用户不满意：

1. 用户提出一条反馈
2. 我修改
3. 等待用户下一条反馈
4. 重复，直到用户满意

未收到反馈时不得继续修改。

## 命名灵感

当用户要求命名、路径位置、新建 crate / 模块 / 目录时，主动检查布局，禁止直接写入，提议多个方案（各含名称和位置），规范参照项目约定、语义清晰、生态惯例，并给出你的推荐。

## 前置任务

用户可能中途添加前置任务，前置任务也是阶段。当添加之后，应该自动识别为最优先的前置任务（stack push），更新状态图。严格按 stack push 优先级顺序执行。前一个未完成时，不得开启后一个。

## 阶段未完成标志

- 用户未要求进入下一阶段
- 有未 commit 的改动

如果当前阶段未完成，不能处理下一阶段的任务。
