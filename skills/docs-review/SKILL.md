# docs-review — 文档 slop 审查

本清单由**当前 agent 逐条自查**，**不启动 subagent**、不外派审查。

## 审查清单

### 1. 目录注释穷举
结构树/目录布局里给目录写注释时，只注释「目录的角色定位」，**禁止逐文件/逐主题穷举**（「架构 + X 使用 + Y 建模」式追加）。树是结构不是目录页——目录内容它自己的文档自会说明。每加一个新文档就回去给树注释追加一笔 = 维护债信号。

### 2. 状态标注残留
正文出现「现状是 X / 迁移后是 Y」这类句式，或「本次新增 / 已知局限 / 待定 / 待实测」这类标签，= 过程叙事混入。文档描述**当前契约**：「模型是什么、契约是什么」，不写「从哪来、要变成什么」。判断法：把时间线抹掉后这句话还成立吗？不成立就是 slop。

### 3. 「将要做的」占位
计划做的、还没存在的东西写成正文条目 = 待落地清单。要写就写成定义（目标态契约定了就是文档），但**禁止**携带「新增/将要/计划/未来」的框——那个框是实施记录，属 issues / drafts / 会话，不属文档。判断法：全文都依赖「还没实施」这层语境吗？是，就是写作时机错了——要么等实现后写，要么全文按目标态纯定义写。

### 4. 私拍数字量
正文里的数字、阈值、上限（「≤ N 个」「不超过 N 行」「N 轮内」）必须能指出来源：用户原话、体系事实、外部规范。指不出就是自己拍板冒充规范——读者既不能核验，也无从判断它该不该变。判断法：拿这个数字问「谁说的」，答不出就是 slop。

### 5. 声量与实现配比
文档声量必须与代码实现的比重一致：**冲洗**是同一个新概念到处放——散落多个小节、多处重复（每处哪怕只一句），把原有结构稀释掉；**少补**是实现很重（跨多处、改契约）却只补三两句，读者照文档核验不了。新概念只落既有结构（唯一归属小节、复用已有词表与表格），不另起并列章节、不改术语层级。判断法：以文档里该概念的声量为分子（占多少篇幅、出现在几处）、以实现的落点为分母（这次改了几处、动了几个契约点），两者比一比——分子大于分母是冲洗，分子盖不住分母是少补。

### 6. 独立构件自成子标题
独立成件的东西（工具、可执行产物、独立进程、转换遍）要**自成子标题**——形态、职责、限制归它的同级小节；**禁止**塞进别节的段内或长句，父节那处只留一行指针。判断法：把它抽出来看——它有自己独立的形态与边界吗？有，就自成子标题；只是某条规则的一个取值，就留在段内。

### 7. 新条目照原条目规范
往既有结构里加条目（清单项、表格行、小节序列），**照抄原条目的形态**（同字段、同粒度、同量级篇幅），做到并排看不出接缝；**禁止**给新条目另起一套（多一列、换写法、多垫解释）。判断法：与相邻两条并排看，字段、量、口气齐不齐？

### 8. 语气严谨克制，不追加无缝断言
追加两类断言同等禁止：**全面断言**——在陈述后面扩散到全集（「一律」「任何」）；**反向断言**——判掉补集（「否则就是违规」）。病根是同一个：判定封死全部其他情况——**无缝**；判定又写成定论，读者没有余地把它当疑问追问下去——**不留余地**。这条判定从哪来，后来人便无从检查。断言合理的格式是**先铺垫论述、再落结论**：论述摆出来，判定才有出处可指——用户原话、体系事实、外部规范；指不出 = 写者自己拍的假设，落不进文档：删掉，或自己补上论述与出处。判断法：这句判定往上找得到托住它的论述吗？找不到，删掉，或自己补上论述。

### 9. one home per fact
同一个事实**只在一份文档里完整陈述**；他处不复述、不改写措辞。归属由**文档定位**决定——先认这份文档定位上管什么（术语源 / 决策 / 实现 / 过程记录），只把它定位内的事实完整陈述进来；定位外的删掉，需要指路时留一句链接。第二份完整陈述 = 两份迟早不一致，读者不知信哪份，而两份都得跟着改。判断法：落一条事实前先问「它在哪份文档里完整陈述过」——写过且不在本档定位内，删掉或留链接；没写过，先按文档定位选定唯一那份再写；同一条事实在两份的定位里都成立，先收窄定位或把事实拆开：定位相符的那一份完整陈述，定位不相符的那一份留链接，不靠换措辞躲重复。

### 10. 占位词必须闭合
「其他 / 等等 / 若干 / 相关 / 类似」这类兜底词是**清单没穷举的信号**，它代替不了定义。写进正文就必须当场闭合，要么**额外说明它指什么**（「其他 = 临时豁免」），要么**显式排除**（「除 X、Y 外不接受第三种」）。**禁止**兜底词不闭合就充当一个条目、一个取值或一条判据——读者不知道边界在哪，后续也无从判断能不能往这个口子里加东西。判断法：拿这个词问「它覆盖什么、不覆盖什么」——两个问题答不出一个，它就没闭合，是 slop。

### 11. 列表表格按性质限长
正文里的 markdown 列表（有序、无序）与表格，篇幅按它装的东西分档：**代码或事实清单**（结构化）每列文字 ≤ 20 字；**规则** ≤ 10 行、每行 ≤ 约 100 字节；**例子解释** ≤ 3 行。超档 = 载体选错了：说明文字移出单元格、规则提成子标题（第 6 条）、例子压回 3 行或写成正文。判断法：这个列表装的是清单、规则，还是例子？拿对应档位量一量——超档就该换载体。

### 12. 判据不逆推
判据的方向必须与文档的推导方向一致。文档里的推导通常是一条链——**用户决策 → 约束和范围 → 设计思路 → 技术细节（代码）→ 展示（表格、统计信息）**，每级都是上一级的落实：判据只能取上游一侧、顺着推导方向核下游。拿下游的结论去判上游的依据不成立——判据由被判对象推出来，与被判对象不独立；下游依赖上游，上游一变下游就变，判据随被判对象走，改上游就能让下游跟着变「对」，成了循环论证。判断法：这条判据取的是被判对象上游的依据，还是它下游的结论？后者不成立，回上游重判。

### 13. 陈述决策时不写来源
文档陈述决策时不写来源——不摘用户原话（「用户原话：…」这类引文）、不引草稿、不写「见某次会话 / 某条裁决」。来源是写者核验用的，读者要的是决策本身。判断法：这段讲的是决策，还是它从哪来？讲来由的，删掉。
