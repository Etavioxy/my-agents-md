# docs-review — 文档 slop 审查

## 审查清单

### 1. 目录注释穷举
结构树/目录布局里给目录写注释时，只注释「目录的角色定位」，**禁止逐文件/逐主题穷举**（「架构 + X 使用 + Y 建模」式追加）。树是结构不是目录页——目录内容它自己的文档自会说明。每加一个新文档就回去给树注释追加一笔 = 维护债信号。

### 2. 状态标注残留
正文出现「现状是 X / 迁移后是 Y / 新增 M1 / 已知局限 / 待定准 / 待实测」= 过程叙事混入。文档描述**当前契约**：「模型是什么、契约是什么」，不写「从哪来、要变成什么」。判断法：把时间线抹掉后这句话还成立吗？不成立就是 slop。

### 3. 「将要做的」占位

计划做的、还没存在的东西写成正文条目 = 待落地清单。要写就写成定义（目标态契约定了就是文档），但**禁止**携带「新增/将要/计划/未来」的框——那个框是实施记录，属 issues / drafts / 会话，不属文档。若全文都依赖「还没实施」这层语境，说明写作时机错了：要么等实现后写，要么全文按目标态纯定义写。

### 4. 私拍数字量
正文里的数字、阈值、上限（「≤ 6 个」「不超过 120 行」「三轮内」）必须能指出来源：用户原话、体系事实、外部规范。指不出就是自己拍板冒充规范——读者既不能核验，也无从判断它该不该变。判断法：拿这个数字问「谁说的」，答不出就是 slop。
